# Adaptive planetary terrain

`PlanetTerrain` streams six cube-sphere quadtrees using a deterministic 3D height field from `SpaceEngine.Core.TerrainNoise`. This is the rendered surface at every altitude; the application does not replace the planet with a static close-up mesh.

## Integration

Create a `PlanetTerrain` on an identity-scale transform, call `Configure(PlanetDefinition, Material)`, and then call `Tick(cameraFromPlanetMeters, renderScale, planetCenterRender, sunDirection)` once per frame. The supplied material can use shader `SpaceEngine/Terrain`, vertex colors and vertex normals. The sun direction points from the planet toward the star.

`cameraFromPlanetMeters` must be the double precision, planet-relative camera position. The Unity camera must be at the render origin. `planetCenterRender` is accepted for compatibility with the other render systems but is deliberately not used for terrain placement: each patch subtracts the camera from its double precision anchor, scales that double difference, then converts to float. Mesh vertices similarly subtract the patch anchor before conversion. Therefore an Earth-size planet can retain centimeter camera movement at ground level without float cancellation between million-metre values.

## LOD and memory

The selector refines tiles in descending width / closest surface distance order. A conservative analytic horizon test excludes invisible tiles. Maximum level, mesh resolution, leaf count, resident cache count, build count, build time budget and skirt depth are inspector parameters. Defaults are 12 grid cells per patch, level 20, 192 visible leaves, 384 resident records, at most 6 builds / 6 milliseconds per frame. At Earth radius, the smallest patches are about 12 metres wide with roughly one-metre grid spacing. A synchronous build may exceed the time budget by one patch; the count limit is strict.

Parents remain visible until a complete four-child cohort is built. Each child begins at the parent's actual submitted triangles and smoothly acquires its own full seeded geometry. The transition interpolates position, normal, vertex color and raw signed height, using the existing triangle diagonal rather than a bilinear height approximation. Outer skirts begin on the parent's lower skirt; internal child skirts begin collapsed into the parent surface. All three production passes (color, depth normals and depth only) apply the same displacement. Grid resolution is rounded up to an even number so the child triangulation exactly subdivides the parent at the initial endpoint; the default remains 12.

`LodTransitionSeconds` defaults to 0.25 seconds per level; `LodHysteresis` defaults to a 20 percent merge margin and retained-split priority. Refinement proceeds top-down and merging bottom-up, so no transition references an ancestor that is simultaneously changing topology. Reversing travel reverses the current interpolation without a reset. The orbital level-3 floor remains active during approach instead of switching off abruptly at altitude 0.1R. A tiny distant planet still uses the same hierarchy at coarse LOD. Desired leaves retain the configured budget; during a reversible merge a previous child cohort can remain visible temporarily. Resident cache eviction pins active transition cohorts and may temporarily exceed its target to preserve coverage.

Callers can pass explicit elapsed seconds as the optional fifth `Tick` argument for reproducible paths. Default runtime timing uses unscaled frame time, capped at 0.1 seconds per update. `IsSettled` includes both mesh builds and outstanding transitions; `PendingBuildCount == 0` alone is insufficient before a still-frame comparison. `CopyActivePatchStates` exposes stable ordered addresses and morph fractions; `TrySampleRenderedSurface` samples the actual visible triangle representation without changing the authoritative collision/landing height.

Each patch has an inward skirt on every edge. This masks T junctions between different LODs and chart seams. Both triangle windings are explicitly emitted so that the skirt writes depth when seen from either the taller or the lower adjacent tile, even with a backface-culling material. Depth defaults to the larger of four metres or eight percent of tile width. Those parameters are configurable. A resolution-12 tile has 217 vertices and 480 triangles including both skirt sides. Regression tests verify both windings and overlapping actual coarse/fine edge profiles across all six faces from level 12 through 20. Normals come from a shared, fixed physical finite-difference interval in the continuous height field, so an edge has the same normal from both chart parameterizations. The default probe interval is 0.25 metres, configurable through `NormalSampleDistance`, to preserve the seeded six-metre geological relief independently of planet radius. Seeded physical nine-metre and 120-metre material variation complements that geometry in the vertex colors. Ocean geometry is the zero height datum where the seeded terrain lies below sea level; its color varies with the underlying depth. This implementation has no ocean waves, erosion simulation, caves, biome textures, or geomorphing yet. Mesh changes can visibly pop during fast travel; skirts solve cracks, not temporal blending.

## Verification

`Tests/TerrainGeometryTests.cs` includes Unity EditMode checks for chart edge agreement, outward triangle winding on all six faces, complete skirt indices, unit normals, seeded repeatability, centimeter camera precision at Earth radius, continuous boundary normals, bounded LOD streaming and coarse/fine convergence.

Visual review of the first Unity screenshots found that continent-sized noise alone produced nearly planar ground despite level 20 tessellation. The core height field now includes bounded physical 10 km / 1.6 km / 200 m / 25 m / 6 m bands. A dedicated mesh regression test measures radial second differences after removing local slope, ensuring that metre-size cells carry actual shape. After this correction, an Earth-size level 20 dry patch measured 0.1394 m maximum local second difference, 0.1397 adjacent normal change and 0.0214 adjacent green-channel material change. Sixty resolution-12 CPU payload builds averaged 1.610 ms with those detail bands; the earlier 1.161 ms result below predates their addition.

On 2026-10-26, an additional isolated .NET Release harness compiled the terrain and core sources against the installed Unity 6000.5.7f1 managed assemblies. Geometry checks passed; a level 20 patch had an 8.604 m corner offset from its double origin. Sixty resolution-12 patch payload builds averaged 1.161 ms each (217 vertices, 384 triangles). This measures CPU payload generation, not native mesh upload or GPU frame time.

The same selector was exercised outside Unity with its native shader-property initializer bypassed only in a temporary copy: for 192 leaves, representative altitudes of 100,000 m, 1,000 m and 2 m selected 45 / level 6, 115 / level 13 and 190 / level 20 tiles respectively. Native renderer correctness still requires actual Unity screenshots and player frame measurements.

## Surface material revision

The original visible material inherited the 12 by 12 vertex grid in every patch. Refining geometry to improve an orbital coastline also spent CPU time on terrain meshes, while quarter-metre normals aliased at orbital distances. The revised material separates those two sampling problems.

`TerrainMaterialMap` dispatches a compute bake the first time a solid body occupies a useful screen area. Its six `RFloat` cube faces default to 1024 by 1024 pixels, with a full trilinear mip chain: approximately 32 MiB per allocated body. The resolution is configurable from 64 to 2048. Distant bodies do not allocate a map. Destruction or a system change releases the texture. The map stores signed physical height, rather than a hand-painted color image. The shader reproduces `TerrainNoise.Height`, including the 64-bit SplitMix gradient hash, continental/hill/ridge bands, metre-scale bands, crater parameters and lava troughs. Portable `uint2` arithmetic avoids relying on a different GPU hash. CPU geometry, landing heights, seed version and save data are unchanged.

The fragment shader derives coastlines and typed biome albedo from that same signed height. Ocean roughness and reflection differ from land. Pixel footprints filter orbital surface gradients and physical detail bands; a coarse orbital mesh no longer interpolates arbitrary quarter-metre normals across entire continents. Near the ground, the material blends to exact raw vertex heights supplied in `TEXCOORD1` and the original geometric normals. Physical pixel footprints come from camera-relative positions divided by render scale, rather than differentiating a planetary unit direction. Fine material normals use analytic three-dimensional noise gradients. Sub-metre material grain uses a periodic 16,384 metre chart: the double CPU anchor is reduced before conversion to float, and integer noise wraps agree across neighbouring patches. That detail modulates material and normal response; it does not replace physical relief or change collision height.

`MaterialMapResolution`, `MaterialDetailStrength`, `SurfaceNormalStrength`, `OceanRoughness` and `OceanSpecularStrength` are runtime component controls. `MaterialMapReady`, `MaterialMapBytes` and `LastMaterialBakeCpuMilliseconds` expose allocation and submission telemetry. The CPU submission time does not measure completed GPU work. GPU tests dispatch the actual production compute shader and read back signed-seed noise, typed heights, shared face edges and mip levels; their height tolerance accounts for float direction normalization in the six-metre band at planetary radius.

The finite map still has a resolution limit; at the default an Earth-sized face has roughly 12 km sample spacing near its chart centre. Close-range geometry provides the finer zero contour, and filtered procedural material adds smaller visual frequencies. This is not satellite imagery, erosion simulation, or streamed photogrammetry. The current face mip generation is independent per chart; base edge directions agree, while very distant minified chart borders may retain a small filtering difference.

### Actual ground and atmosphere regressions

The first revised orbital screenshots improved coastlines, but a complete flight exposed two defects that the isolated material-chart render did not cover. Both failures and controls are retained.

- `Space Engine/Validate Ground Terrain Pixels` builds the actual origin planet and its adaptive meshes, retains double planetary anchors, places the observer at two metres above the same dry landing direction as the flight route, and captures a near-horizon view. Differentiating a normalized planet direction had approximately half-metre float quantization at this radius, producing random fine normals. The original failed checker residual was **0.0319873**, with a **0.0582014** image difference after a two-millimetre camera movement. Camera-relative footprints and analytic material gradients reduced those values to **0.0000121** and **0.0000211**. A twofold render-scale change produced zero image difference. The five checks use unchanged thresholds. Failure evidence remains under `Artifacts/V030/GroundPixels/OriginalDirectionNormals`; corrected captures are under `CameraRelativeGradients`.
- `Space Engine/Validate Ground Atmosphere Pixels` adds the production `AtmosphereRenderer` to that same real terrain fixture. The configured Forward+ renderer enables SSAO from depth normals. URP therefore requests a `DepthNormalsOnly` prepass; a shader with only `DepthOnly` was absent from the camera depth texture even though its opaque terrain was visible. The atmosphere consequently fell back to the sea-level sphere and drew a hard horizontal reference horizon across real hills. Adding the matching `DepthNormalsOnly` pass restored measured terrain depth coverage from **0 to 1** and reduced the atmosphere-only maximum horizontal row step from **0.0137188 to 0.000005354**. All seven composition/precision checks passed with their original thresholds. Both `MissingDepthNormals` and `DepthNormalsPresent` evidence directories are retained beneath `Artifacts/V030/GroundAtmospherePixels`.

The terrain normal prepass uses the same geometry as the color/depth passes, follows URP's world-normal/oct encoding and supports `_WRITE_RENDERING_LAYERS`. The scattering model was not weakened or bypassed to conceal the missing-depth defect. Final gameplay screenshots and standalone-player acceptance remain separate from these controlled GPU checks.

### Continuous approach regression (0.4)

The original geometry was deterministic but still changed visibly during descent: full-frequency samples at successive LODs had different triangle interpolation, and complete children replaced their parent in one frame. A single threshold and an altitude-gated orbital floor could also repeatedly change the selected tree. Near-range material blended from the geological map to those changing vertex heights based on camera altitude. The revised path retains the same generation-v2 `TerrainNoise.Height` and final fine geometry, adds reversible representation transitions and hysteresis, and ties material ownership to actual morphed mesh sample spacing.

`TerrainLodContinuityTests` covers parent endpoints on all six faces, including a requested odd resolution; identical height/color/normal inputs; stationary 120-frame stability; threshold jitter; a return trip; and continuous descent/reversal under a two-build frame limit. `Space Engine/Validate Terrain LOD Pixels` renders actual planetary parent/child geometry with the production shader and map. Its eight checks compare parent and child endpoint images, a tiny interpolation step, retained full detail, repeat/return frames, and the actual Forward+ camera depth texture. Reports and seven PNG controls are written to `Artifacts/V040/TerrainLodPixels`. These controlled checks do not replace the continuous player video or all-seed/long-session testing; actual results must be read from the generated report rather than inferred from successful compilation.

The first actual RTX4070/D3D12 fixture passed all eight checks: parent/child-start mean RGB difference was `0.00000186968`, compared with `0.0155140` for the complete fine-detail endpoint. A 0.001 morph step changed the image by `0.0000110143`; repeated hold and reversal images had zero difference. The camera-depth endpoint difference was `0.00000030324`. Initial CPU endpoint tests additionally found float centre/extents rounding in incremental `Bounds.Encapsulate` could exclude an earlier fine vertex; culling bounds now use one extrema calculation over both endpoints with a conservative float-ULP margin. Geometric and material endpoint tolerances remain unchanged.

## Research basis

- Filip Strugar, [CDLOD reference implementation and paper](https://github.com/fstrugar/CDLOD): regular-grid quadtree patches and three-dimensional distance-based refinement. This implementation uses CPU generation, exact parent-triangle geomorphing and skirts; it does not claim the complete CDLOD selection/error model.
- Asirvatham and Hoppe, [GPU Gems 2, Terrain Rendering Using GPU-Based Geometry Clipmaps](https://developer.nvidia.com/gpugems/gpugems2/part-i-geometric-complexity/chapter-2-terrain-rendering-using-gpu-based-geometry): bounded regular grid blocks, active detail according to altitude, and streaming tradeoffs.
- [Ellipsoidal Cube Maps for Accurate Rendering of Planetary-Scale Terrain Data](https://doi.org/10.2312/PE/PG/PG2012short/005-010): planetary coordinate precision and cube chart representation. The current procedural body is spherical rather than an ellipsoidal geodetic dataset.
